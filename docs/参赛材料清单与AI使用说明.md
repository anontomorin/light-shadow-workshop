## 二、生成式 AI 工具使用说明

### 2.1 使用的工具

| 项 | 内容 |
|---|---|
| 工具名称 | 【WorkBuddy / CodeBuddy 等，请按实际填写】 |
| 提供方 | 【腾讯，或实际提供方】 |
| 使用的模型 | 【如 Deepseek-V4.1-Flash，请按实际填写】 |
| 使用时间 | 【2026-10 上旬 — 2026-10-15，请按实际填写】 |
| 使用方式 | 以「代码 Agent」方式使用：把重构规格文档与现有仓库一起交给它，由它审计源码、编写代码、运行测试脚本 |

### 2.2 具体使用环节

1. **规格理解与仓库审计**
   把重构规格包交给 AI，并要求它**先读真实代码再动手**（不采信旧文档中未经验证的假设）。AI 输出了基线清单：现有 6 关的关卡数据、投影与匹配模块、存档 key、e2e 脚本的前置条件等。
   第二轮（v3.0.0：中国风重做 + 二级入口 + 扩形状 + 加花窗题目）同样要求 AI 先复查上一轮的产物与遗留问题。

2. **代码编写**
   由 AI 生成新增模块：纹样生成器（`src/patterns/`）、窗格文档与杆件几何（`src/window-builder/`）、多构件投影（`src/projection/WindowProjector.ts`）、投影诊断读数、工坊玩法与界面、文化数据层、作品存储与海报导出。
   第二轮又由 AI 完成：投影核心从"整物体一次凸包"改为**凸块分解 + 逐块凸包 + 并集**（`src/scene/GeometryFactory.ts`、`src/projection/Projector.ts` 的 `projectParts()`、`src/scene/StudioScene.ts` 的多零件 Group）、
   形状从 6 种扩到 14 种、关卡从 6 关扩到 10 关并新增花窗构件工具箱（`src/data/levels.ts`）、
   新增二级入口页（`src/ui/ModeSelect.ts`）、重写标题页与关卡分组（`src/ui/TitleScreen.ts`、`src/ui/LevelSelect.ts`）、
   以及三张样式表的中国风重做（`src/styles/global.css` / `screens.css` / `components.css`）。
   第三轮又由 AI 完成：标题页右侧改为**三扇真实花窗的轮播**（`src/ui/TitleScreen.ts` + `src/styles/screens.css`），
   朱砂印章改为显示当前窗棂样式名；并把全局字体替换为中国风（正文宋体系、标题与题签楷体系，仍为零网络字体）。
   第四轮由 AI 完成**字号梯度与版面复核**：把 87 处硬编码字号收敛成 `--fs-*` 六个梯度
   （正文改宋体后 10–12px 明显累眼，故整体上调且越小加得越多），
   并同步调整随字号连动的固定尺寸（滑块标签 / 数值列、快捷键小标签、指引卡宽度、侧栏列宽、输入框高度等）。

3. **测试脚本编写与执行**
   由 AI 编写 `scripts/verify-window.ts`、`scripts/check-prod-hook.mjs`、`scripts/capture-evidence.mjs`，扩展 `scripts/e2e-check.mjs`，并由它实际执行这些命令。
   第二轮同步更新了验证范围：`verify-window` 新增"复合构件与凹形镂空"一节（54 项）、`verify-levels` 覆盖 10 关、
   `e2e-check` 从 93 项扩到 174 项（把入口流程改为"首页 → 光影挑战 → 影形解谜 / 自由实验室"，新增工坊版面回归断言、首页花窗轮播与中国风字体断言，
   以及用真实鼠标事件驱动绘制模式、验证"节点标识 / 过程预览 / 退出路径 / 退出后仍可点选"的 17 项回归）。

4. **文档撰写**
   由 AI 根据**实际运行结果**整理 README、文化资料来源表、技术说明与测试报告；测试报告中的数值全部来自真实命令输出。

### 2.3 人工完成的部分

- **选题、产品定位与玩法设计**：把「传统窗棂」与「几何投影」结合的创意，以及"必须保留窗格空隙"这一核心技术要求，来自规格文档与人工决策。
- **第二轮方向决策**：以花窗工坊为主题的中国风重做、把两个旧玩法收进二级入口、扩充形状与花窗题目，均由人工提出并逐条给出验收标准。
- **文化内容的取舍与措辞**：模板名称、来源清单、以及「数字示意 / 风格化创作」等边界声明，由人工依据官方来源逐条确认。
  花窗题目标题（方格窗 · 十字棂 / 菱花窗 · 三交六椀 / 冰裂纹 · 碎影 / 窗棂总成 · 圆光窗）同样按公开资料命名，并在文末明确"参数化几何是本项目的数字再设计"。
- **验收与判断**：所有"通过"结论都由人工复跑命令确认；测试失败时由人工判断是"实现有 bug"还是"测试写错了"。
  第二轮里"花窗题目精对齐只有 0.73–0.78"一度看起来像 bug，经人工判断确认是**细长棂条的几何性质**，
  因此改为**按实测可达性重新标定阈值**，而不是放松校验或伪造数据。
- **参数校准**：关卡阈值、复杂度上限、圆环段数等数值由验证脚本实测校准后由人工确认。

### 2.4 关于"AI 生成内容"的边界声明

- 本项目**所有图像都是程序实时渲染或程序绘制的矢量图形**（Three.js 实时渲染 / Canvas 2D / SVG），**未使用**任何 AI 图像生成模型，也**未使用**来源不明或许可不清晰的图片素材。
  中国风界面同样**零位图素材**：宣纸底、窗棂暗纹、回纹角、印章、纸纹全部由 CSS 渐变 / 伪元素 / 内联 SVG 绘制；字体只用**系统本地**字体栈（正文宋体系、标题与题签楷体系），**不加载任何网络字体**，因此断网或离线打开 `dist/` 的渲染完全一致。
- 窗棂纹样为**参数化程序生成**，属于数字再设计，界面与文档中均标注为 **「数字示意」** 或 **「风格化创作」**，不声称复原任何具体文物或建筑构件。
- 文化叙述仅复述官方来源明确记载的内容，并逐条附带来源链接；未从单篇文章推演其未明确说明的历史结论。
